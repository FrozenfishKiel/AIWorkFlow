# 前台内容结果页收口计划

## 目标

把当前偏“技术工作台 / 操作者后台”的前端，收口成面向内容团队的前台内容结果页。

这次收口不是单纯调布局，而是把主界面目标改正：

- 用户不是来“看任务状态”的
- 用户是来“输入内容并拿到可继续编辑的内容结果”的

## 这次为什么必须做

当前仓库虽然已经有异步主链、理解结果、检索、工作流结果和导出能力，但默认页面仍然把这些中间能力组织成了后台视角：

- 任务列表放在前台高优先级位置
- 导出历史和状态快照直接暴露给普通用户
- 知识索引和后台记录与主结果同级展示
- 用户输入内容后，第一感知仍然像“创建了一条任务”，而不是“拿到了一份结果”

如果继续沿着这个方向迭代，产品会越来越像技术演示台，而不是内容团队真正会用的内容处理器。

## 本次收口范围

### 1. 正式产品主线

- 前台默认主线改成：`输入内容 -> 查看结果 -> 修改/导出`
- 主结果默认收口为“可发文案 / 可继续编辑文案”
- 理解结果、检索参考、工作流建议改为服务主结果的辅助区

### 2. 前台首屏重排

- 保留输入区
- 把当前结果区提升为首屏主区域
- 任务列表降级为最近任务/历史记录区
- 导出历史、知识索引、状态快照、后台记录下沉

### 3. 结果内容收口

- 当前结果页优先显示：
  - 主改写稿
  - 风格/平台备选版本
  - 风险点
  - 待确认项
  - 可复用素材拆解

### 4. 后台信息下沉

- 审计时间线
- 后台记录
- 导出历史
- 知识索引
- 任务链路状态

这些内容仍然保留，但不再作为普通用户首屏主内容。

## 实施方式

### 工作流 A：文档与产品约束收口

- 把“前台不是技术工作台，而是内容结果页”正式写入技术方案
- 明确主结果与后台辅助信息的层级关系

### 工作流 B：前台信息架构收口

- 调整页面层级，结果优先，历史与后台信息下沉
- 让新任务创建后直接进入当前结果区，而不是继续用后台列表心智

### 工作流 C：结果产物收口

- 把现有理解/检索/工作流字段重新组织到“内容产物”下面
- 后续继续补“改写稿、多版本、风险提示、素材拆解”这些真正面向内容团队的输出

## 完成标准

完成后，至少满足下面这些条件：

- 用户输入内容后，首屏先看到的是当前结果，不是任务后台
- 页面主内容不再是导出历史、知识索引、当前任务状态
- 最近任务只作为历史入口存在
- 后台信息存在，但默认下沉
- 技术方案已经明确写入新的产品收口方向

## 暂不扩的范围

这次先不把工作扩大成完整的内容编辑器或多页面发布系统，不做：

- 富文本在线编辑器
- 外部平台自动发布
- 团队协同评审流
- 多角色内容审批系统

这次目标只有一个：先把前台从“技术工作台”改成“内容结果页”。
