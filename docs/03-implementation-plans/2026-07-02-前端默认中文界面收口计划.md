# 前端默认中文界面收口计划

## 目标

把当前任务工作台从“英文默认界面”收口为“中文简体默认界面”，并把这条约束正式沉淀到工程实现里，避免后续新增功能继续混入英文用户文案。

## 这次为什么必须做

这个项目当前面向的人，包括你自己、面试官、项目评审者和潜在试用用户，默认都是中文语境。页面主界面、任务状态、登录提示、知识登记、导出记录如果继续保留英文，会直接带来三类问题：

- 产品定位和真实用户画像不一致
- 演示时第一观感明显割裂
- 后续开发容易在没有统一规则的情况下继续把英文写回去

所以这次中文化不是“视觉润色”，而是 Phase 1 可演示上线口径的一部分。

## 本次收口范围

### 1. 正式规则

- 把“默认产品语言是中文简体”写进正式技术方案
- 把“新增用户可见文案默认先写中文”固化成当前工作流规则

### 2. 前端用户可见文案

- 首页头部
- 登录页
- 新建任务表单
- 知识登记与详情区
- 任务列表
- 任务详情
- 审计时间线
- 导出历史
- 状态快照

### 3. 通用状态与元数据文案

- 任务状态
- 导出状态
- 知识索引状态
- 审计事件标签与说明
- 空状态、加载状态、失败提示、下载提示

### 4. 自动化验证

- 调整现有 Web 单元测试，断言关键入口默认显示中文
- 检查状态帮助函数输出是否已经切到中文
- 跑 `scripts/qa/verify.ps1 -Scope web`

## 实施方式

### 工作流 A：文档规则收口

- 更新正式技术方案，明确默认产品语言
- 把中文化从“页面改字”升级成产品规则和工程约束

### 工作流 B：统一文案源收口

- 优先把用户可见通用文案集中到前端统一文案层
- 页面组件、状态映射、说明文本都从统一文案层取值
- 避免后续某个组件单独硬编码英文

### 工作流 C：页面替换与回归

- 按页面逐块替换英文文案
- 补关键中文断言测试
- 用统一验证脚本检查构建、测试和基础质量

## 完成标准

完成后，至少满足下面这些条件：

- 主工作台不再出现成片英文用户文案
- 任务状态、知识状态、导出状态默认显示中文
- 登录、任务创建、知识登记、任务详情、导出区都能以中文阅读
- 技术方案已经明确写入“默认中文界面”的产品约束
- Web 验证通过

## 暂不扩的范围

这次不把工作扩大成完整国际化平台改造，不做：

- 多语言切换器
- locale 路由
- 词条管理后台
- 英文/中文双语同时维护

这次目标只有一个：先把当前 Phase 1 工作台真正收口成中文默认界面。
