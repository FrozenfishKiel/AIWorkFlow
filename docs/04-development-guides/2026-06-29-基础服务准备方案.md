# 基础服务准备方案

## 这份文档现在的职责

这份文档只负责说明当前仓库的基础服务准备与冷启动基线，不再假装承担“完整生产部署已完成”的结论。

## 当前基础服务

- PostgreSQL
- Redis
- MinIO
- FastAPI API
- Celery worker

## 当前准备结论

- 本地开发需要的基础服务组合已经齐了。
- 统一运行时目录已经收口到仓库根目录 `.runtime/`。
- 本地 compose 配置可校验、可启动、可联调。
- 生产 override 目前还不能被当成“已验证的端口收口配置”。

## 冷启动顺序

1. 确认 Docker Desktop 可用。
2. 在仓库根目录执行：

```powershell
docker compose -f infra/docker-compose.yml up -d
```

3. 如需校验配置，执行：

```powershell
docker compose -f infra/docker-compose.yml config
docker compose -f infra/docker-compose.yml -f infra/docker-compose.prod.yml config
```

4. 再运行仓库统一校验：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/qa/verify.ps1 -Scope all
```

## 现阶段不要说满的话

- 不要说 MinIO 已经进入应用主链，当前上传/导出还是 `.runtime/`
- 不要说 pgvector 检索已落地，当前是最小词法检索
- 不要说生产 override 已经彻底关闭外露端口，这一点目前没有被验证结论支持
