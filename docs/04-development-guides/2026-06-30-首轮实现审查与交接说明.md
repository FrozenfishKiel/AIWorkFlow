## 3. 本轮重点收口

### 3.1 已收口的责任边界

- 审核不是摆设按钮，审核动作走后端状态机
- 导出不再读可变的原始草稿字段，只读 `approved_snapshot`
- 审核中的本地草稿不会被轮询静默覆盖
- 驳回后重跑路由先校验状态，再入队，不再允许非法状态先偷偷进 Celery
- 已支持最小 Bearer 访问门禁
- 文件任务已从前端接到专用上传接口
- 导出制品已通过 API 下载路由收口，不再要求前端消费裸文件路径
- 任务已支持可选 `knowledge_domain`，检索不会再默认全库无差别命中
- 文件任务已改为读取真实上传文本参与理解与检索
- URL 任务已改为抓取公开 HTML 并做基础正文抽取，不再只是占位文本
- 根目录 acceptance 测试已经接入统一校验脚本

### 3.2 已补上的高价值注释

本轮补注释的重点不是“每行解释一遍”，而是把最容易出责任事故的地方写清楚：

- review / approved snapshot / export authority
- SSRF 与上传边界
- pipeline / retrieval / knowledge indexing 当前哪些是占位实现，哪些输出契约已经被上下游依赖
- 前端审核草稿同步与已批准快照优先级
- 最小 Bearer 访问门禁的启用条件与作用范围

## 4. 现在仍然没完成的地方

这些不是“忘了做”，而是客观上还没落地：

- 真实模型驱动的理解与生成
- 向量检索、pgvector 实际检索链
- LangGraph 实际业务编排
- URL 任务更稳的文章级正文抽取、清洗和失败恢复
- 登录、用户体系、细粒度权限控制
- 独立 `AuditLog` 审计实体
- 知识索引 UI
- 完整导出管理页
- 压力测试
- 更完整的风险测试资产

## 5. 当前最重要的诚实边界

### 5.1 能说“已经有”的

- 真异步主链
- 真审核门
- 真审核后导出快照
- 真知识索引与最小检索
- 真最小 Bearer 访问门禁
- 真 acceptance 校验入口

### 5.2 不能说“已经有”的

- 生产级 RAG
- 正式权限体系
- 正式审计系统
- 完整生产部署收口
- 完整导出产品体验

## 6. 已知风险

### 6.1 技术风险

- 当前检索是最小词法检索，效果和鲁棒性都不能等同于生产 RAG
- 当前 URL 任务虽然已经有基础 HTML 正文抽取，但还不是成熟的文章级抽取与清洗链
- 生产 override 仍未证明已经完全收口对外端口
- 当前上传/导出还是本地 `.runtime/` 路径，不是对象存储主链
- 当前 Bearer 门禁只是最小访问门，不是完整认证体系

### 6.2 测试风险

- acceptance 现在覆盖的是“当前已实现最小闭环”，不是整项目最终形态
- 压力测试还没做
- 前端还没有浏览器级 e2e smoke

## 7. 接下来建议的顺序

1. 先做更真实的知识链和 RAG
2. 先把 URL 任务文章级抽取与失败恢复、知识评测和更深 retrieval 验证补牢
3. 再补访问控制与审计链
4. 再补风险测试与压力测试
