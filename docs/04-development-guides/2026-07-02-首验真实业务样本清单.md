# 首验真实业务样本清单

这份清单只服务一件事：

- 让你知道第一次真实验收时，具体要给我什么材料

它不是长期知识库规范，也不是最终运营规范。它只为当前这版项目做第一次“像真实用户那样跑”的验证准备。

## 一、最少要给哪几类东西

第一次真实验收，建议你给我四类材料。

### 1. 真实知识资料

这是给 RAG 用的。

建议至少给：

- `3 到 8` 份品牌/业务规范
- `2 到 5` 份历史优质内容或参考样例
- `1 到 3` 份审批、合规、发布前检查规范

文件类型优先：

- `md`
- `txt`
- `docx`
- `pdf`

每份资料最好能告诉我：

- 资料标题
- 属于哪个业务域
- 这份资料大概管什么

你可以按这个格式给：

```text
标题：品牌语气规范-2026版
业务域：brand
用途：约束文案语气、禁用表达、对外口径
文件：xxx.docx
```

### 2. 真实任务样本

这是给“任务输入 -> 理解 -> 检索 -> 生成 -> 导出”整链路用的。

建议至少给：

- `5 到 10` 条真实任务

任务来源可以混着来：

- 纯文本任务
- 文件任务
- URL 任务

每条任务最好带：

- 输入内容
- 任务目标
- 希望参考哪个业务域
- 你觉得这条任务最容易出错的点

你可以按这个格式给：

```text
任务名：新品活动预热文案整理
输入类型：text / file / url
业务域：content-ops
任务目标：把输入内容整理成后续可写作的任务工作流结果
关注点：不要夸大宣传；要保留证据来源；要指出待确认项
文件或链接：xxx
```

### 3. 你认可的“好结果”样本

这不是必须很多，但非常有用。

建议给：

- `2 到 5` 条你认为写得对、结构对、口径对的参考结果

它的作用不是让系统照抄，而是让我判断：

- 输出风格偏什么
- 结构颗粒度要多细
- 什么叫“这结果能继续往下用”

### 4. 明确不能犯的错误样本

这个很重要，哪怕只有几条也值钱。

建议给：

- `3 到 10` 条你最不能接受的问题

例如：

- 引用不到位
- 语气不对
- 审批口径说错
- 把待确认项写成确定事实
- 明明该命中某份规范却没命中

你可以直接写成：

```text
不能犯的错：审批前不能把“待确认价格”写成确定价格
不能犯的错：品牌文案不能出现过度承诺
不能犯的错：导出结果里不能丢掉关键证据来源
```

## 二、如果你现在时间不够，最小交付是什么

如果你现在不想一次准备很多，那第一次最小可用包可以是：

- `3` 份真实知识资料
- `3` 条真实任务样本
- `1` 条你认可的好结果
- `3` 条不能犯的错误

有这一包，我就能开始做第一轮更真实的人工验收支撑。

## 三、哪些信息最值钱

如果你只能优先给一部分，优先级是：

1. 真实知识资料
2. 真实任务样本
3. 不能犯的错误
4. 好结果样本

原因很简单：

- 没有真实知识资料，RAG 验证会偏假
- 没有真实任务样本，主链只能停留在占位场景
- 没有错误边界，就很难判断“跑通”和“能用”的区别

## 四、你给我的时候怎么放最省事

最省事的方式是你在仓库里新建一个目录，比如：

- `tests/samples/real-first-pass/`

然后按这种结构放：

```text
tests/samples/real-first-pass/
  knowledge/
  tasks/
  references/
  notes.md
```

其中：

- `knowledge/` 放知识资料
- `tasks/` 放真实任务输入
- `references/` 放你认可的好结果或反例
- `notes.md` 写业务域、用途、注意事项

## 五、哪些东西现在先不用给

第一次首验前，不用急着给这些：

- 大批量全量历史库
- 几百条任务
- 很细的账号权限规则
- 很完整的上线运维材料
- OCR 相关单独资料

现在我们要的是“能证明项目在真实业务内容上站得住”的第一包，不是一次把所有资产接管完。

## 六、我收到后会怎么用

我会用这批材料做四件事：

1. 替换掉当前占位知识资料
2. 跑真实任务，检查理解、检索、工作流结果、导出、审计链
3. 看哪些任务是主链问题，哪些任务是知识资料问题，哪些是召回问题
4. 形成第一轮更真实的验收问题单

## 七、你现在可以直接照抄的最短提交模板

如果你想最短路径给我，可以只写一个 `notes.md`，像这样：

```md
# 首验样本说明

## 业务域
- brand
- content-ops

## 知识资料
- 品牌语气规范.docx
- 发布前审批规则.pdf
- 历史优质样例.md

## 真实任务
- 任务1：新品活动预热文案整理
- 任务2：外部文章转内部选题建议
- 任务3：活动页内容抽取与风险点提示

## 不能犯的错
- 不能把待确认信息写成确定事实
- 不能丢证据来源
- 不能忽略审批约束
```

有了这份最短模板和对应文件，第一轮真实验收就能开始。
