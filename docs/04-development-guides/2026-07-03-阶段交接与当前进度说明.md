这份文档是给下一个接手这个仓库的 AI 看的。

它不重复写完整需求，也不替代正式技术方案。它只做四件事：

## 一、当前项目已经收口到什么方向

当前项目正式方向已经不是最早那版“内容任务工作台 / URL 解析 / 泛知识库问答”。

现在仓库正式收口为：

`电商商品内容生产系统`

当前主线是：

`商品基础信息 + 任务描述 -> 商品理解 -> 固定电商资料利用 -> 卖点提炼 -> 三类内容初稿 -> 风险提醒 / 参考依据 -> 导出`

这个方向已经体现在：

- `README.md`
- `docs/01-project-specs/2026-06-29-项目需求与环境准备方案.md`
- `docs/02-architecture/2026-06-29-项目正式技术方案.md`
- `docs/03-implementation-plans/2026-07-03-电商商品内容生产系统收口实施计划.md`

后续接手时，不能再把项目往这些方向拉回去：

- 任务列表首页
- 任务工作台心智
- URL 主链
- 通用知识库问答产品壳
- 多 Agent 平台化
- 导出中心壳

## 五、当前还没做完，或者应该继续盯的点

当前不是“项目完全结束”，而是已经进入一个更像成品、可以继续人工测试和持续收尾的阶段。

下一个 AI 接手时，优先继续看这些点：

### 1. 做完整用户流人工测试时，还要继续盯

- 输入一组真实商品信息后，结果质量是否稳定
- 三类初稿是否共享同一套商品叙事
- 风险提醒是否足够像真实业务约束
- 参考依据是否真的对用户有解释价值
- 导出结果是否适合直接给运营继续编辑

### 2. 前端仍然有一些可以继续收口的小问题

这些不是大方向问题，但值得继续修：

- 浏览器页签标题目前还是旧名称，需要与当前项目正式名称对齐
- 首屏视觉已经成型，但如果后续还要继续商业化，可以再做更细的排版打磨
- 结果页当前以“结构清晰”为优先，后面可以继续强化“像产品产物而不是调试页面”的感觉

### 3. 后端和产品层面还要继续诚实面对的边界

当前仍然不要误报这些能力：

- 真实 embedding RAG 已完全成熟

## 七、接手后的第一步建议

不要一上来就继续“凭感觉改页面”或者“再补功能”。

建议按这个顺序开工：

1. 先把上面列出的文档看完
2. 先看 `git log --oneline -5`
3. 跑一次当前需要的验证命令
4. 先判断当前最值钱的剩余问题到底是产品结果质量、人工测试暴露的问题，还是某个明显的工程残留
5. 再决定先改哪一段

如果只是继续收前端，就先从完整用户流角度看问题，不要回到“加说明卡”“加后台模块”这种旧思路。
